## Color Palette

All colors are defined in `Cardio Tracking/DesignSystem/RT.swift` as adaptive tokens via `UIColor` dynamic providers — no asset catalog required. **Never hardcode hex values in views — always use the `RT.Color.*` token.**

**2026-08-01 — recolored to match the Figma "movethink" color-system file** (light: node `140-1140`, dark: node `95-5553`). That file's own variable palette is deliberately small — five tokens total: `Background/Background`, `Text/Body`, `Text/Body Secondary`, `Stroke/Grey 1`, and `Background/Chart Value`. It expresses every card/track/chip surface as one flat ink-tinted overlay (`Background/Background 10%`, ~4% alpha in practice) rather than a stepped ladder. This app still needs more than one surface step (card vs. track vs. progress-trough vs. active-lift all need to read as visually distinct), so the five literal Figma values are reproduced exactly, and everything the Figma file doesn't define (`surface1`–`surface4`, `hairlineStrong`, `hairlineTertiary`, `inkMuted`, `inkTertiary`) is now derived as `ink.opacity(_:)` at increasing alpha — the same mechanism the Figma file itself uses for its one surface tone, just extended to the number of steps this app's screens actually use. This self-adapts to both themes for free (always relative to whatever `ink` resolves to) and replaces the previous generation's hand-picked flat hex values for those tokens.

The overall palette also shifted from a cool near-black/near-white pair to a **warm** one (cream `#FAF8F5` / warm near-black `#131312`, vs. the previous generation's `#FCFCFD` / `#0A0A0C`) — this is a real hue change, not just a lightness tweak, straight from the Figma file's literal values.

There are also **two distinct "maximum contrast" concepts**, not one — don't conflate them:
- `ink` / `background` carry the warm tint above — this is normal text/background.
- `inverseCanvas` / `inverseInk` are the *true* stark black/white pair. **2026-08-01: no longer used for primary CTA buttons** — `PillButton`'s `.filled` style, the Onboarding "Continue"/"Set my goal" buttons, and `SubSettingsScreen`'s save button all switched to the flat `hairline` fill + `ink` text look from the sign-in screen ("the button we used on the sign up screen should be the primary button type everywhere," per explicit direction). Still theme-adaptive (flip which is black/white per appearance) and a **different, starker value** than `ink`/`background`, not aliases of them — and still used, unchanged, for **selected/toggle states**: the tab bar's active voice pill, `HomeView`'s active range pill (1W/1M/etc.), `GoalChip`'s selected chip, `HistoryView`'s selected range chip, and `ReviewView`'s selected activity chip. Those are a distinct pattern (an always-on toggle, not a call-to-action) and weren't part of this request. The Figma file doesn't define this pair at all (out of scope for its screens).

`inkMuted`/`inkTertiary`/`surface1-4`/`hairlineStrong`/`hairlineTertiary` being expressed as `ink.opacity(_:)` rather than flat hex is a deliberate mechanism choice, not a placeholder — it mirrors the Figma file's own `Background/Background 10%` pattern and means these tokens can never drift out of sync with `ink` if `ink` itself changes again later.

**design-qa pass (same day):** the first draft's surface steps were spaced 2% apart (4/6/8/10%), which read as visually indistinct — widened to 4/8/12/16% (and `hairlineStrong`/`hairlineTertiary` to 24%/18%) so each step is still legible on its own. Also: because these are alpha overlays rather than resolved flat colors, a surface sitting on top of another surface (e.g. a `surface2` chip inside a `surface1` card, several places in `GoalsView`/`HomeView`) composites to a stronger effective tint than its number implies — acceptable for the occasional nested chip, but worth knowing before nesting three-plus steps deep.

### Legacy aliases (still valid, prefer direct tokens for new work)

A few token names from the prior generation are kept as aliases so existing call sites didn't all need touching in one pass: `chipBackground`/`cardSurface` → `surface1`, `separator` → `hairline`, `cardStroke` → `hairlineStrong`, `buttonBackground`/`buttonForeground` → `inverseCanvas`/`inverseInk`, `accent`/`accentForeground` → `primary`/`onPrimary`, `secondaryText` → `inkSubtle`, `destructive` → `danger`. **New call sites should reach for the direct token**, not the alias — the alias names will likely be retired once every screen has been through this round.

Untouched by this pass (no reference guidance, low-risk to leave): `cycleGreen`, `cycleGreenDim`, `deltaPositive`, `deltaNegative`, `scrim`. The Google "G" logo on the sign-in button is a brand mark and must keep its exact colors regardless of theme.

### Color roles — quick rules

- **Primary text/icons**: `ink`. Step down through `inkMuted` → `inkSubtle` → `inkTertiary` as emphasis decreases.
- **Any surface that floats above the background**: pick the right surface *step* for the context, not just "a surface" — cards are `surface1`, tracks are `surface2`, progress-bar troughs are `surface3`, and an active-state lift on top of a `surface2` track is `surface4`.
- **The lavender accent is scarce, on purpose.** It marks exactly: the chart's selected bar, a goal's progress-bar fill, and a couple of focus/press states. It never fills a card, never becomes a background, and never appears as a second accent alongside another color.
- **Primary CTA buttons** (`PillButton`'s `.filled` style — Save/Record/Stop/Review, plus Onboarding's Continue/Set-my-goal and Settings' save button) → flat `hairline` fill + `ink` text, matching the sign-in screen. **2026-08-01: no longer `inverseCanvas`/`inverseInk`** — see the token table note above.
- **Selected/toggle states that aren't buttons** (active voice tab, active range pill, `GoalChip`/`HistoryView`/`ReviewView`'s selected chip) → still `inverseCanvas` fill + `inverseInk` content, unchanged. Everything else that needs a "selected" look (the Mood/Distance toggle's active segment, a regular nav tab's active state) uses the subtler `surface4` lift instead — don't reach for `inverseCanvas` by default just because something is "selected."

## Chart (`HomeView`'s Mood/Distance chart) — hard-won lessons, still true

- Flat bar chart (`BarMark`, 6pt fixed width, 4pt corner radius), no gridlines, no axis labels, no background gradient. Tap-to-select + a callout annotation (date + value bubble) — **this interaction is being kept through this round unchanged**, only recolored.
- **Selection must stay a single mark, opacity/color-driven — never two stacked marks.** Two `BarMark`s at the same x-position stack (sum their heights) in Swift Charts by default; an earlier round hit this as a real bug (the "selected" bar shot up past the plot area). Selection is expressed by changing one mark's `foregroundStyle`, never by drawing a second mark on top.
- This round's recolor: unselected bars → `hairlineStrong`; selected bar → `primary` (lavender) — a real shift from the prior generation's monochrome ink-opacity selection, since this system's whole point is that the accent marks exactly this kind of "the one selected thing."
- Callout tooltip uses `calloutBackground`/`calloutForeground` (→ `surface2`/`ink`) — a data tooltip, not a CTA, so it deliberately does **not** use the stark `inverseCanvas` pair.
- **Three chart variants now coexist on purpose, all fully built out — this is a live A/B/C, not a leftover.** `BarTrendChart` (the flat-bar chart above, now with an optional `showAxes` flag), `BarTrendChart` again with `showAxes: true` (bars, but with the same gridlines/labels treatment as the area chart, for a fair side-by-side), and `AreaTrendChart` (smooth line + `primary`-tinted gradient fill under the curve, our own tap-to-select callout reused rather than the reference mockup's, plus visible axis gridlines/labels). Axis chrome for both the bars-with-axes variant and the area chart is factored into one shared `TrendChartAxes` `ViewModifier` so the two "with axes" looks are pixel-identical, not two different treatments that happen to look similar. `MoodChart`/`DistanceChart` both switch on a single `private enum ChartStyleOption { case bar, barWithAxes, area }` / `private let chartStyleOption` — **do not delete any chart implementation** while this switch exists; it's there so the user can compare all three before picking one. Remove the switch and the losing variants once a style is chosen. Current value: `.barWithAxes`.
- `AreaTrendChart` takes a `showYAxisValueLabels: Bool = true` parameter — `MoodChart` passes `false`. Mood's Y-domain is numeric (`0.0...5.0`) internally but the chart's own content (callout, legend) is always a word ("Rough"..."Great"), never a number, so bare decimal ticks like "2.5" would contradict the chart and read as meaningless. The horizontal gridlines stay (a numberless gridline is still useful for eyeballing trend), only the tick numbers are suppressed. Distance keeps numeric labels since distance values are meaningful numbers.

## Font bundling

Geist ships as static-weight `.ttf` files (not a variable font) so `Font.custom(_:size:)` lookups stay simple — each weight is its own named font (`Geist-Regular`, `Geist-Medium`, `Geist-SemiBold`, `Geist-Bold`, `Geist-Black`, `Geist-Light`). Licensed under SIL OFL 1.1 (`vercel/geist-font` on GitHub) — free to bundle. Files live at the top level of `Cardio Tracking/` (an Xcode 16 file-system-synchronized group — no manual "add to target" step needed) and are declared in `Cardio-Tracking-Info.plist`'s `UIAppFonts` array alongside `Pacifico-Regular.ttf`.

## Dark Mode

Fully adaptive via `UIColor` dynamic providers in `RT.swift`. When adding new colors, use the `dynamic(_:dark:)` helper and pick the correct surface *step* deliberately (see "Color roles" above) rather than defaulting to the nearest existing token.

  - **Waveform demoted**: `RT.Spacing.waveformHeight` 130 → 36, active-bar color `RT.Color.ink` → `RT.Color.hairlineStrong`, and it moved from the centered hero position to a small strip directly above the Manual/Stop controls — an ambient "audio is still coming in" signal, not the main visual.
  - The "Tell me about your activity" prompt shrinks to a single muted line while recording (the transcript has taken over), and disappears entirely once there's a captured transcript to show (`.done`/`.parsing`) rather than sticking around as a stale "still listening" style prompt above content that's already been captured — an early draft left the shrunk prompt showing in all three non-idle states, caught by design-qa.
  - `entryState` transitions (idle → recording → done) now animate (`​.animation(.easeInOut(duration: 0.2), value: entryState)` on the containing `VStack`, `.transition(.opacity)` on the swapped transcript views and the waveform strip) instead of popping instantly — an early draft had none of this and reviewer feedback (design-qa) called out the layout changes as jarring.
  - Reviewed by code-reviewer (PASS — confirmed `.defaultScrollAnchor` is valid at the iOS 18 deployment target, no main-actor race between the live view and the stop-time transcript snapshot, and the shrunk `waveformHeight` doesn't degenerate the bar-drawing math) and design-qa (3 minors — headline over-broad-shrink, missing transition animation, missing crossfade — all fixed above).
